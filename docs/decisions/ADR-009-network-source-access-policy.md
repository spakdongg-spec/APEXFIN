# ADR-009: 网络数据源访问策略——不实现任何规避访问控制的行为

## Status

Accepted (2026-08-02) — 裁决人 team-lead（大湾区靓仔），起草 高见远

由 `docs/decisions/OPEN-DECISIONS.md` O-03 关闭后升格。O-03 的裁决具备长期约束力，且约束的是「所有网络源」而不止 Yahoo 一家，故单列 ADR。

## Background

APEXFIN 的全部说服力建立在一件事上：**它是一套关于数据诚实性的参考实现**。质量门、降级态、观点对账、fail-loud，卖点都是「不骗自己」。

而 APEXDATA 的 `scripts/pipeline/fetch_yahoo.py` 里有两段东西与此直接冲突：

1. **User-Agent 轮换池**——每次请求从一组浏览器 UA 中随机取一个。
2. **双 host 回退**——主端点失败后自动改打另一个 host。

这两段的唯一用途是绕过对方的访问频率控制。在私人仓库里它只是「让脚本别断」，一旦进入公开仓库，性质就变了：

- 法律与平台风险：Yahoo Finance 没有公开数据 API 的商业授权，其服务条款限定个人非商业用途并反对自动化批量抓取。仓库里带一段专门规避其访问控制的代码，是主动把自己放到条款的对立面。
- 声誉风险：一个以「数据治理与诚实性」为主张的项目，代码里藏着伪装身份的逻辑，这是自己拆自己的台。任何一个读源码的人都会先注意到这一点。
- 而它换来的收益近乎为零：demo 默认路径走 committed fixture，根本不访问 Yahoo（ADR 见 `ARCHITECTURE.md` 十）。Yahoo 只是一条可选的进阶路径，风险敞口本就很小，没有为它承担上述代价的理由。

## Decision

**本项目不实现任何规避访问控制的行为。** 适用于当前与未来的所有网络数据源，不限于 Yahoo。

具体到实现：

1. **单一公开端点**。每个网络源只允许一个 host 常量。禁止 host 数组、禁止回退链、禁止镜像站轮询。
2. **固定标识性 User-Agent**，格式 `apexfin/{version} (+https://github.com/<repo>)`。禁止浏览器伪装串，禁止 UA 池，禁止随机化。
3. **保守速率**，默认请求间隔下限 1.5 秒。配置项只允许调大，不允许调小。
4. **访问控制信号即停**。收到 429 或 403 时抛 `SourceBlocked`，立即结束本源采集并写入 `quality_findings`，不重试、不换 host、不降速再试。
5. **退避只对瞬时网络故障生效**。连接超时与 5xx 走 `BaseCollector` 的通用退避；429/403 不属于此集合。这条区分写进 `sources/base.py` 类文档——否则后续实现者很自然就会把 429 顺手并进重试集合，规避行为就这样回来了。
6. **demo 默认路径零外部请求**，走 committed fixture。
7. **免责声明**写进 README 与 `sources/yahoo.py` 文件头：数据用途限个人研究与教育，使用者需自行遵守数据源服务条款，本项目不分发任何数据。
8. Stooq CSV 端点作为**文档化备选，MVP 不实现**。`BaseCollector` 抽象使这个替换只影响一个文件，判定 Yahoo 风险不可接受时再切。

### 可测约束（S10 实现时逐条对照）

| # | 约束 | 校验方式 |
|---|------|----------|
| C1 | `sources/` 下不存在 UA 列表/池/轮换 | AST 门禁：`sources/` 内禁止 import `random`，禁止 `User-Agent` 字面量集合 |
| C2 | 每个网络源只有一个 host 常量 | 单测断言 `YahooCollector.HOST` 是 `str` 而非序列 |
| C3 | UA 为固定标识串 | 单测断言 UA 含项目名与仓库地址，不含浏览器伪装串 |
| C4 | 429/403 不重试不换 host | 单测：mock 429，断言请求次数 == 1 且 `CollectResult.status == "blocked"` |
| C5 | 请求间隔下限 1.5 秒，可调大不可调小 | 单测：设 `min_interval=0.1` 被夹到 1.5 |
| C6 | demo 零外部请求 | `make demo` 在 socket 被 monkeypatch 禁用的环境下仍需退 0 |

C1 是这套约束里唯一一条机器可判的「意图检查」。它会误伤合法的 `random` 用途（例如抖动退避），因此限定只在 `sources/` 包内生效，其他层不受限；确需抖动时用 `core/` 提供的封装，不在采集器里直接摇随机数。

## Consequences

正面：
- 消除法律与声誉风险敞口，代价接近于零（demo 本就不走网络）。
- 「不规避」从一句主张变成六条可测断言，新贡献者提 PR 加回 UA 池会被 CI 直接拦下，而不是靠 reviewer 记性。
- 采集器实现变简单：没有回退链就没有「到底是哪个 host 成功了」这类状态，错误路径唯一。

负面：
- Yahoo 端点在高频调用下更容易被限流，进阶路径的可用性下降。**这是有意接受的**——被限流时正确行为就是停下并如实记录 finding，这恰好也是本项目要演示的质量门行为，负面后果与产品主张同向。
- 单 host 无冗余，对方端点变更即该源不可用。缓解：`SourceUnavailable` 走退出码 5，语义明确；`BaseCollector` 抽象使换源只改一个文件。
- C1 的 AST 规则是启发式，能拦住直白写法，拦不住刻意混淆。这条边界写在门禁注释里，不假装它是完备的。
